# The Vulnerable Interface

A research prototype designed to study user reactions to different types of error states in web interfaces.

## Overview

This project is a visual design research tool created to test and observe how users react to various error messages and states in web applications. The prototype presents multiple error scenarios in a controlled environment, making it ideal for UX research and usability testing.

## Features

### Six Error State Scenarios

1. **Form Validation Errors** - Real-time validation feedback for email and password fields
2. **Network Errors** - Connection failure simulations
3. **System Errors (500)** - Internal server error demonstrations
4. **Permission Denied (403)** - Access restriction scenarios
5. **Timeout Errors (408)** - Request timeout simulations
6. **Rate Limit Errors (429)** - API rate limiting demonstrations

## How to Use

### Running the Prototype

1. Clone this repository
2. Open `index.html` in a web browser
3. No build process or dependencies required - it's pure HTML, CSS, and JavaScript

### For Research Participants

1. Navigate through each scenario card
2. Click buttons or submit forms to trigger error states
3. Observe your reactions and feelings to each error type
4. Use the "Reset All Scenarios" button to clear all errors and start fresh

### For Researchers

- This prototype can be used for:
  - Qualitative user research sessions
  - A/B testing different error message styles
  - Measuring emotional responses to error states
  - Identifying user pain points in error handling
  - Teaching UX design best practices

## Technical Details

- **Pure Frontend**: No server or backend required
- **Responsive Design**: Works on desktop and mobile devices
- **No External Dependencies**: Self-contained HTML, CSS, and JavaScript
- **Accessibility Considerations**: Semantic HTML and clear error messaging

## Research Applications

This prototype can help answer questions like:
- How do users react emotionally to different error types?
- Which error messages are most clear and actionable?
- Do technical error codes help or confuse users?
- What information do users need when encountering errors?
- How does error presentation affect user trust?
